PROCESS

How Pulse works

  • 01

    Fetch

    Independent async fetchers query 2–3 sources per domain simultaneously. No single point of failure. Each fetcher is isolated and timeout-bounded.

    ~10s refresh
  • 02

    Aggregate

    Median aggregation filters outliers. String values use voting consensus. Numeric spread percentage tells your agent how much sources disagree.

    Median + voting
  • 03

    Score

    Confidence starts at 0.6 for 2 sources, +0.10 per additional source, capped at 0.95. Your agent knows exactly how much to trust the answer.

    0.6 → 0.95
  • 04

    Deliver

    Redis cache provides sub-millisecond reads on warm data. HTTP pull or WebSocket push. Works with LangChain, AutoGen, CrewAI, or any custom agent.

    <1ms cached
FAQs

Here's what you need to know before integrating Pulse into your agent.

  • A single API call is one unverified node. Pulse queries 2–3 independent sources per feed, computes the median, scores confidence based on agreement, and tells your agent exactly how much to trust the result. If sources disagree beyond threshold, Pulse returns DEFER — not a wrong answer.
  • Confidence starts at 0.60 for any 2-source feed, increases by 0.10 per additional verified source, and is capped at 0.95. A score of 0.87 means 3 sources agreed within a tight spread. Your agent can use this to decide whether to act, wait, or escalate.
  • Pulse exposes a standard HTTP JSON API and WebSocket stream. The Python SDK wraps it in one import. LangChain, AutoGen, CrewAI, and any custom agent that can make an HTTP request can use Pulse out of the box.
  • Background fetchers run every ~10 seconds. Redis cache serves warm reads in sub-millisecond. On a cold miss, Pulse fetches fresh and responds within 200–500ms. On-chain data follows 12s Ethereum block time as the natural floor.
  • Yes. Full source on GitHub — Rust core (axum + tokio + redis), Python SDK, evaluation harness, Docker compose. MIT licensed. Self-host in one command: docker-compose up.
